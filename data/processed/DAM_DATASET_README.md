# DAM-Integrated 2014-2023 Dataset

Generated by:

```bash
./venv/bin/python data/build_dam_price_dataset.py
```

Main output:

```text
data/processed/dataset_2014_2023_with_dam_prices.csv
```

Forecast-runner output:

```text
data/processed/dataset_1980_2023_with_dam_prices_for_forecast.csv
```

The forecast-runner file keeps the pre-2014 rows so the causal ridge wind model can train on historical data before the 2014-2023 backtest. DAM columns are available beginning in 2011 so the augmented price model can learn how DAM relates to RTM before testing.

What it contains:

| Column | Meaning |
| --- | --- |
| `datetime` | Project timestamp |
| `power_generated` | Existing project Pyron-style wind generation column |
| `rtm_lmp_pyron_usd_per_mwh` | Existing realized RTM LMP used for scoring |
| `user_load_zonal` | Existing project zonal load column |
| `dam_lz_west_spp_usd_per_mwh` | ERCOT Day-Ahead Market SPP for `LZ_WEST` |
| `dam_hb_west_spp_usd_per_mwh` | ERCOT Day-Ahead Market SPP for `HB_WEST` |
| `*_was_interpolated` | `True` only where the project's continuous timestamp exists but ERCOT DAM skipped the spring daylight-saving 02:00 hour |

How to use it in the future experiment:

1. Plan dispatch using forecast wind plus one DAM price column.
2. Execute dispatch chronologically under storage constraints.
3. Score realized revenue using `rtm_lmp_pyron_usd_per_mwh`.

This does not replace the frozen RTM benchmark. It is a separate future experiment.

Important limitation: the pulled annual ERCOT DAM SPP archive does not include `PYR_PYRON1`, so this file uses West DAM prices as the day-ahead planning signal and keeps Pyron RTM LMP as the realized scoring signal.
